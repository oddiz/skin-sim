# skin-sim: local flap simulator for plastic surgery

## Goal
A simulator where the user designs local flaps around a skin lesion, cuts, grabs and slides
skin, sutures edges together, and sees how well the defect closes (tension, distortion).
Long term: research grade and publishable. Current goal: a tinkerable prototype, a flat
rectangle of skin that can be cut, dragged and sutured, with tissue properties adjustable
live via sliders while the simulation runs.

## The user
Doctor training in plastic surgery; full-stack developer (strong Python, servers, APIs).
New to C++, Godot and 3D. Explain what you do and why, especially build tooling and C++
concepts. Define abbreviations on first use. Teach the reasoning, not just the code.

## Platform and tools
- Dev machine: Windows. Later target: iPhone (built on a Mac later; out of scope now).
  Keep all code portable: no Windows-only APIs.
- Godot 4.7, standard build (not .NET).
- C++ via GDExtension using godot-cpp, built with SCons and MSVC (VS 2022 Build Tools).
  - godot-cpp is versioned independently of Godot since v10. Use a godot-cpp 10.x tag
    and pass `api_version="4.7"` to its SConstruct (there is no `4.7` branch).
- Vendored libraries (git submodules pinned to tags/commits), all permissive:
  - godot-cpp (MIT)
  - Eigen (header-only, MPL-2.0). Always define `EIGEN_MPL2_ONLY`. Built-in sparse solvers
    only; no CHOLMOD/PARDISO/other wrappers.
  - CDT by artem-ogre (header-only, MPL-2.0): constrained Delaunay triangulation.
  - doctest (single header, MIT): unit tests.
- Forbidden: Shewchuk's Triangle, any GPL code. Keep THIRD_PARTY_LICENSES up to date.
- Do not add any other dependency without asking the user first.

## Architecture
- `/solver`: standalone C++ library, zero Godot dependency. All mechanics live here.
  Builds and runs headless; tests in `/solver/tests`. Must stay verifiable against
  reference FEM software and wrappable for Python later.
- `/extension`: thin GDExtension layer exposing solver classes to Godot as nodes.
  No physics logic here.
- `/game`: Godot project. GDScript for UI, input, scene logic.

## Physics design (built in stages)
- Skin = 2D plane-stress membrane on a linear triangle mesh. Epidermis/dermis are a visual
  distinction only (layered cut-edge walls); dermis dominates mechanically.
- Material: incompressible plane-stress membrane. Neo-Hookean (M2), plus isotropic exponential
  strain-stiffening W = mu/(2b)(exp(bQ)-1) (M3, Demiray; b=0 recovers Neo-Hookean); then
  Gasser-Ogden-Holzapfel (GOH) anisotropic fibres, with
  fibre angle representing relaxed skin tension lines (RSTL).
- Tethering: per-node spring to the underlying base; undermining brush lowers tether
  stiffness locally.
- In-vivo prestress parameter so cut edges gape realistically.
- Quasi-static solve: Newton iterations with line search and step clamping, a few
  iterations per frame so dragging feels live. Must stay stable at extreme slider values
  (stiffen, never explode).
- All tissue parameters live in one struct that may change between frames; the solver
  simply relaxes to the new equilibrium.
- Cutting: on committing an incision polyline, re-mesh with CDT. CDT does no quality
  refinement, so: seed evenly spaced interior points + denser points along cuts,
  triangulate, then a few Laplacian smoothing passes to avoid slivers.
- Grabs (forceps): pull spread over a radius (area-weighted, so results converge with mesh
  refinement), force-capped spring (Huber energy); solved via Woodbury identity, never a dense block.
- Sutures: constraint pulling two edge points together.
- Output per element: stress values for a heatmap (vertex colours).

## Rendering and input
- 3D scene, top-down orthographic camera (2D-like now; tilting later reveals cut-edge layers).
- Sheet = ArrayMesh updated each frame.
- Touch input from the start (screen touch/drag events), with mouse-to-touch emulation
  enabled for desktop testing.

## Milestones
- M0: Toolchain check + "hello" GDExtension: one C++ custom node printing a message in the editor.
- M1: Rectangle mesh generated by the solver library, rendered in Godot.
- M2: Neo-Hookean solver with tethering; drag a node with the mouse, sheet responds.
- M3: Live sliders for all tissue parameters + JSON presets.
- M4: Incisions with CDT re-meshing.
- M5: Sutures and stress heatmap.
- M6: Undermining brush, GOH fibres, prestress.
- (after M6: suture bite strips with loop stress; lip contact between incision edges.)
- M7: Lesion excision and defect closure: lesion markings, fusiform excision design, removal of
  pieces of skin cut free, margins, min principal stress heatmap (dog-ear compression).
- M8: Wrinkling membrane (tension-field theory): relaxed energy min over D >= 0 of W(C + D),
  blended with the flat membrane by a "wrinkling" fraction (default 0.9 in the app, 0 in the
  solver) so elements cannot invert; excess skin heatmap (where dog-ears pucker).

## Planned features
- Local flaps (advancement, rotation, transposition) on excision defects.
- Friction between the lips; calibration against measured skin properties.

## Working rules
- One milestone at a time. At the end of each: stop, give exact verification steps, wait
  for the user's go-ahead.
- Explain install commands before running them. If a tool is missing, give install steps
  rather than guessing.
- Commit to git at the end of each milestone with a clear message.
- Code readable and commented at the "why" level; the user wants to understand the solver.
