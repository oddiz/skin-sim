# skin-sim: local flap simulator for plastic surgery

## Goal
A simulator where the user designs local flaps around a skin lesion, cuts, grabs and slides
skin, sutures edges together, and sees how well the defect closes (tension, distortion).
Long term: research grade and publishable. Current goal: a tinkerable prototype, a flat
rectangle of skin that can be cut, dragged and sutured, with tissue properties adjustable
live via sliders while the simulation runs.

## The user
Doctor training in plastic surgery; full-stack developer (strong Python, servers, APIs).
New to C++, Godot and 3D. Explain what you do and why, especially build tooling and C++
concepts. Define abbreviations on first use. Teach the reasoning, not just the code.

## Platform and tools
- Dev machine: Windows. Later target: iPhone (built on a Mac later; out of scope now).
  Keep all code portable: no Windows-only APIs.
- Web build (showcase): Emscripten 4.0.20 (must match Godot 4.7.2's official web templates),
  `scons platform=web threads=no`, Godot "Web" export preset (extensions on, threads off).
  GitHub Actions deploys it to Vercel (`.github/workflows/deploy-web.yml`). See README.
- Godot 4.7, standard build (not .NET).
- C++ via GDExtension using godot-cpp, built with SCons and MSVC (VS 2022 Build Tools).
  - godot-cpp is versioned independently of Godot since v10. Use a godot-cpp 10.x tag
    and pass `api_version="4.7"` to its SConstruct (there is no `4.7` branch).
- Vendored libraries (git submodules pinned to tags/commits), all permissive:
  - godot-cpp (MIT)
  - Eigen (header-only, MPL-2.0). Always define `EIGEN_MPL2_ONLY`. Built-in sparse solvers
    only; no CHOLMOD/PARDISO/other wrappers.
  - CDT by artem-ogre (header-only, MPL-2.0): constrained Delaunay triangulation.
  - doctest (single header, MIT): unit tests.
- Forbidden: Shewchuk's Triangle, any GPL code. Keep THIRD_PARTY_LICENSES up to date.
- Do not add any other dependency without asking the user first.

## Architecture
- `/solver`: standalone C++ library, zero Godot dependency. All mechanics live here.
  Builds and runs headless; tests in `/solver/tests`. Must stay verifiable against
  reference FEM software and wrappable for Python later.
- `/extension`: thin GDExtension layer exposing solver classes to Godot as nodes.
  No physics logic here.
- `/game`: Godot project. GDScript for UI, input, scene logic.

## Physics design (built in stages)
- Skin = 2D plane-stress membrane on a linear triangle mesh. Epidermis/dermis are a visual
  distinction only (layered cut-edge walls); dermis dominates mechanically.
- Material: incompressible plane-stress membrane. Neo-Hookean (M2), plus isotropic exponential
  strain-stiffening W = mu/(2b)(exp(bQ)-1) (M3, Demiray; b=0 recovers Neo-Hookean); then
  Gasser-Ogden-Holzapfel (GOH) anisotropic fibres, with
  fibre angle representing relaxed skin tension lines (RSTL).
- Tethering: per-node spring to the underlying base; undermining brush lowers tether
  stiffness locally.
- In-vivo prestress parameter so cut edges gape realistically.
- Quasi-static solve: Newton iterations with line search and step clamping, a few
  iterations per frame so dragging feels live. Must stay stable at extreme slider values
  (stiffen, never explode).
- All tissue parameters live in one struct that may change between frames; the solver
  simply relaxes to the new equilibrium.
- Cutting: on committing an incision polyline, re-mesh with CDT. CDT does no quality
  refinement, so: seed evenly spaced interior points + denser points along cuts,
  triangulate, then a few Laplacian smoothing passes to avoid slivers.
- Grabs (forceps): pull spread over a radius (area-weighted, so results converge with mesh
  refinement), force-capped spring (Huber energy); solved via Woodbury identity, never a dense block.
- Sutures: constraint pulling two edge points together.
- Output per element: stress values for a heatmap (vertex colours).

## Rendering and input
- 3D scene, top-down orthographic camera (2D-like now; tilting later reveals cut-edge layers).
- Sheet = ArrayMesh updated each frame.
- Touch input from the start (screen touch/drag events), with mouse-to-touch emulation
  enabled for desktop testing.

## Milestones
- M0: Toolchain check + "hello" GDExtension: one C++ custom node printing a message in the editor.
- M1: Rectangle mesh generated by the solver library, rendered in Godot.
- M2: Neo-Hookean solver with tethering; drag a node with the mouse, sheet responds.
- M3: Live sliders for all tissue parameters + JSON presets.
- M4: Incisions with CDT re-meshing.
- M5: Sutures and stress heatmap.
- M6: Undermining brush, GOH fibres, prestress.
- (after M6: suture bite strips with loop stress; lip contact between incision edges.)
- M7: Lesion excision and defect closure: lesion markings, fusiform excision design, removal of
  pieces of skin cut free, margins, min principal stress heatmap (dog-ear compression).
- M8: Wrinkling membrane (tension-field theory): relaxed energy min over D >= 0 of W(C + D),
  blended with the flat membrane by a "wrinkling" fraction (default 0.9 in the app, 0 in the
  solver) so elements cannot invert; excess skin heatmap (where dog-ears pucker).

- M9: Suture strength and editing: threads by USP size snap at their knot-pull strength
  (thread tension = closing force / 2) once the sheet is at rest, worst first; switch to turn
  off. Per-suture loosen / tighten / cut (undoable), thread swap. Sutures coloured by load;
  "smart" labels (selected, > 75% load, hovered).
- M10: flap tool. Pick a flap type (advancement, rotation, rhomboid), drag from a lesion
  outward: designs the excision around it and the flap together (solver/flaps.hpp, rest
  coordinates), preview + panel parameters, then cuts, removes and undermines in one undo
  step (Sheet::make_flap). "Tie key sutures"; base stress readout.

- UI revision (plan: UI1 foundation, UI2 phone + navigation, UI3 tissue drawer, UI4 guidance):
  UI built in code under game/ui/ (style.gd tokens + Theme, app_shell, context_panel per tool,
  tissue_drawer, param_row). Inter font (OFL) + Lucide icons (ISC). Mark (pen) tool: markings
  in rest coordinates (SkinSheet.to_rest / rest_to_world). Simulation::map_rest_polyline
  (solver/src/marks.cpp) samples them every 0.5 mm and splits them at incision lips (cached
  as material points per mesh); lesion outlines use it too. The overlay caches the projected
  markings until the render version or the view changes.
  Plan / Operate modes: ContextPanel.TOOLS[i].plan; the bar shows one mode's tools,
  switch at the rail's head (AppShell.mode_selected -> main.set_planning). Plan tools: Lesion,
  Pen (MARK), LINE, RECT, CIRCLE, RULER, ANGLE, ERASE (main.Tool; numbers are --tool values,
  only append). Markings {kind, rest, color, style}; shapes built in rest coords (_shape_mark,
  15 deg snap); ruler/angle labels "as drawn -> now" via SkinSheet.rest_point_now; overlay
  _draw_styled (dash/dot pattern continuous along the path). --demo-plan, --mode plan.
  Lesions: type per lesion (SkinSheet.lesion_kind / lesion_kinds_: 0 BCC, 1 SCC, 2 melanoma;
  drawing only), drawn by the skin shaders (looks/lesions.gdshaderinc, procedural, rest mm;
  Look.set_lesions); the overlay draws discs only for Classic / colour maps. Margin tool
  (Tool.MARGIN): tap a lesion = panel margin, drag = any; marking kind "margin". --demo-lesions [--margins].
- Scenarios (UI4): game/scenarios/*.json (README there), game/scenario.gd (start, draw_approach,
  score, probe), ui/scenario_card.gd (picker / case / report), "Cases" top-bar button. Score from
  SkinSheet.get_closure_metrics (open area via oriented lip edges, mean added tension, excess p99);
  references from --probe-scenario n. Cases use pin_boundary false (pinned finite patch = absurd forces);
  drape hole and wound bed are inset by the glued margin so retracted edges show cloth. --scenario n [--approach] [--check].
  UI2: narrow layout (< 820 logical px: bottom tool bar + pull-up context sheet), UI scale
  from the screen's pixel density (content_scale_size = window / scale), two-finger pan/pinch
  with gesture arbitration (main.gd _touch_down), wheel / right-drag / Home on desktop.
- Flap catalogue: 11 designs in solver/flaps.cpp (FlapType numbers are stored: never
  renumber), teaching text in game/ui/flap_catalog.gd. Island flaps (V-Y, keystone) are not
  undermined in the middle (pedicle). Z-plasty is marker-only (flaps would cross in 2D).
- Tension map: stress relative to resting skin (Simulation::resting_stress), auto scale
  (92nd percentile, 1-2-5 steps, hysteresis), contour shader (UV.x = scale position),
  principal-direction strokes (SkinSheet.get_tension_lines), value under the pointer.
- Graphics (plan G1-G4: Classic / Illustration / Realistic / Game looks, switchable in View):
  game/looks/look.gd + .gdshader files; SkinSheet skin/wall/bed_material slots and per-vertex
  shader data (UV rest mm, UV2 (J, lip distance), COLOR (undermined, excess, squeeze dir));
  cut walls = sloped bands; relief normals. Lip-to-lip edges (sharp flap tips) get a render-only midpoint with its
  true lip distance (SkinSheet bridge_mid_/render_tris_), else the wet rim floods the triangle. Renderer: gl_compatibility everywhere (web parity).
  Screenshots: --look N --plain --zoom X.
  G2 Realistic (look 2): skin_realistic.gdshader (bumps from rest-space noise, fake SSS in
  light()). Drape: glued on the skin's margin by the skin shader (window_half, rest
  coords), continued by drape.gdshader on a plane below the wound bed (main.gd); visual
  only. Bleeding: blood pools in the wound bed only (user removed blood on the lips);
  main._update_bleeding -> Look.update_wound(level, fresh).
  Realistic polish: Look.msaa/fxaa (Realistic: FXAA, no MSAA = half the GPU time),
  skin types (Look.SKIN_TYPES, --skin-type 1..6), drape plane is a frame (main._build_drape),
  --bench / --msaa / --fxaa, render stats in Solver details.
  Skin hooks (main.gd): each grab has its own id (_next_grab_id, touch -> id in _grab_of), so

  labels go past the thread's right end (overlay _beyond_end), buttons past the left end.

  Per-frame cost: SkinSheet caches legend / tension lines / lesion & flap info until

  G3 Game (look 3): skin_game.gdshader (cel bands, outline in px), game_background.gdshader
